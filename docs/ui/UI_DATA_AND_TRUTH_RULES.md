# UI Data and Truth Rules

## Data categories
### Verified production data
Actual API/source data. May be presented as factual.

### Development fixtures
Used during UI development. Isolate clearly in code and never silently present as live authoritative data.

### Placeholder copy
Allowed for layout only. Must not contain fake factual claims.

## Never fabricate
- BIS standards
- IS numbers
- titles
- clauses
- certification requirements
- testing requirements
- announcements
- dates
- statistics
- government contacts
- official URLs
- compliance percentages
- accuracy scores

## Evidence
If a claim has no evidence, do not present it as verified. Prefer:
“Information not verified from the available sources.”

## AI output
Use labels such as:
- AI interpretation
- AI-assisted summary
- Source evidence

## Uncertainty
Avoid false precision. Use qualitative states only when supported by backend logic.
