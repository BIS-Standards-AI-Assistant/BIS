# UI Design System

## Character
Authoritative, restrained, accessible, information-rich government service.

## Visual language
Prefer:
- white/light neutral surfaces
- BIS-compatible navy and blue
- restrained institutional accents
- thin borders
- modest shadows
- strong typography
- generous whitespace

Avoid:
- neon
- excessive gradients
- glowing effects
- heavy shadows
- excessive pills
- decorative 3D art
- AI-themed imagery

## Layout
Use a centered responsive content container and full-width header. Use two-column layouts only when useful. Evidence may use a split view. Do not use a permanent dashboard sidebar.

## Typography
Readable hierarchy:
- service/display heading
- section headings
- component headings
- body
- metadata
- evidence text

## Color semantics
Primary: institutional navy/blue.
Neutral: white/light gray/dark text.
Status: green verified, amber attention/uncertain, red error, blue information.
Never communicate meaning by color alone.

## Components
Header, Navigation, SearchBox, ExampleQuery, ServiceCard, StandardCard, StandardTable, EvidencePanel, EvidenceCitation, ProductContext, ClarificationQuestion, StatusBadge, Alert, EmptyState, ErrorState, LoadingState, Breadcrumbs, Footer, FilterBar.

## Cards
Use cards only for meaningful groups. Do not card-wrap every paragraph.

## Buttons
Use concrete service language:
- Search
- View standard
- Inspect evidence
- Compare
- Continue

Avoid vague labels such as Magic, Generate, Enhance.

## Responsive
Desktop is information-rich. Tablet reduces columns. Mobile stacks content and preserves primary actions.

## Motion
Subtle state transitions only. Respect reduced-motion preferences.
